# 中断请求的用量与结算

本次参考 `kiss-kedaya/sub2api` 的固定提交 `2fb59635e90f98e9977bb189c500ca251cb52dd3`，将缺失用量估算接入现有网关、账务事务和去重流程。没有引入另一套余额或异步补扣机制。

## 计量规则

- 按字段保留上游真实用量，包括明确报告的零。初始事件中的占位零不代表整轮免费；最终真实用量覆盖对应的估算。
- 输出使用“已确认累计用量 + 此后实际收到但未计量的尾部”。估算只覆盖收到的文本、可见思考和工具调用名称/参数，不猜测断开后上游生成的内容。
- 尾部 ASCII 字符占比达到 80% 时按约四字符一个 Token，否则约一个 Unicode 字符一个 Token；各分片累计后再取整。
- 缺失输入根据最终实际发送的请求体估算，上限 2,000,000 Token；95% 按缓存读取价，剩余 5% 按普通输入价。这是估算优惠，不是真实缓存命中。已有 `ForceCacheBilling` 优惠继续按原逻辑生效。
- 已报告的输入、缓存读取和缓存写入桶保留，不用估算覆盖。OpenAI 的输入总量与 Anthropic 的普通输入桶按各自协议转换。
- 估算缓存读取仅在价格未配置时回退普通输入价；明确配置的零价保留免费。实际缓存用量的历史定价行为不变。
- 输入估算剔除已知 base64、内联文件、加密内容和签名；Responses 的 `previous_response_id` 不会被展开成猜测的隐藏上下文。过大或无效的捕获内容放弃估算，不使用截断 JSON。

HTTP 请求捕获上限为 32 MiB；HTTP 响应观察器的单个 OpenAI 事件或非流式 JSON 上限为 2 MiB，Anthropic/Gemini 为 4 MiB。超过上限的捕获内容放弃解析，不据此猜测不可见用量。WebSocket 继续遵循现有消息大小限制，其计费去重 ID 与上游真实 `response.id` 分开，没有后者时不自动创建下一轮上下文引用。

## 取消、故障与重试

客户端在首个输出前取消，仅在请求已经实际写入上游连接或已获得接受响应时，才可能补算缺失输入。未发送请求、本地校验拒绝、明确上游拒绝及无输出的上游故障不因此产生估算费用。真实已报告用量仍按现有账务规则处理。

客户端取消或响应写入失败会取消上游请求并关闭响应体。只处理已经收到的内容，不继续无限读取上游以等待最终 usage。流式与非流式、转换协议和原生协议遵循相同原则。

每次上游尝试独立保存发送状态、请求体和用量。可重试的失败尝试不会与后续成功尝试重复估算。WebSocket 按轮独立处理，复用现有结算回调和请求去重；断开后不再读取余下终态。

图片、固定工具费用、模型与渠道倍率、订阅、API Key 配额、余额和原子去重仍走现有费用计算与事务。

## 账单来源标识

用量 API 和导出包含：

| 字段 | 含义 |
| --- | --- |
| `input_tokens_estimated` | 输入含缺失部分的估算 |
| `cache_read_tokens_estimated` | 缓存读取桶包含估算优惠 |
| `output_tokens_estimated` | 输出含实际收到的未计量尾部估算 |
| `usage_estimation_reason` | `client_cancelled`、`upstream_eof`、`upstream_timeout`、`upstream_error` 或 `missing_usage` |

用户用量、管理员用量和最近请求独立显示这些标识。输入或缓存为估算时不展示真实缓存命中率；输出估算提示明确保留已确认前缀。

迁移 `341_add_usage_log_input_estimation.sql` 只增加默认值为 `false`、`false`、空字符串的三列。没有历史账单重算、回填或补扣。
