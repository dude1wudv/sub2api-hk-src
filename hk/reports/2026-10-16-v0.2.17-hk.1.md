# Sub2API HK v0.2.17-hk.1

## 更新内容

- 同步上游 v0.2.17，保留 HK 智能路由、portal / ink、HeliosGen 和供应商协议边界；包含支付查询与退款保护、Gemini 兼容思考、Responses `created_at` 和模型退休策略等上游修复。
- 普通 Anthropic、API key 透传、国产模型原生 Anthropic 三条流路径统一累计已收到的文本、thinking、工具参数。缺失有效用量时按累计语义 UTF-8 字节数除以 4 向上取整，写入 `output_tokens_estimated`，用户端、管理端和导出均展示估算来源。
- 上游正数真实计数覆盖对应估算；后续新增输出仅估算尚未计量的尾部，零计数不再抹掉已经收到的语义输出。空流保持零，输入和缓存不凭空估算。
- 错误 SSE 的安全 usage 和估算标记可传入结算，保留错误状态；完整尾事件即使缺少末尾换行也不丢用量。底层收到字节即刷新活跃时间，避免长 SSE 行被误判为空闲。
- 新增不含正文、thinking、工具参数或凭据的 `gateway.stream_usage_recovery` 诊断摘要。

业务基线：`1d80e2d39686600293f242b6b9f38a6eb2bca8c6`；本次发行补齐三语 README 与版本说明，不改变该修复的业务逻辑。

## 升级与计费边界

- 相比 v0.2.15-hk.3，包含迁移 `249_add_usage_log_output_tokens_estimated.sql`，历史记录默认 `false`；历史 token、费用和余额不补扣、不重写。若已部署 10 月 15 日的 `b13ee0977f`，本次流修复没有额外 Sub2API 迁移。
- “实时累计”是内存中跟踪已接收内容，请求结束或断流后沿既有 request-id 幂等机制结算一次，不是逐块扣款，也没有崩溃恢复 checkpoint。
- 字节估算不是模型 tokenizer，只覆盖本机已收到的语义内容，不能恢复未传回的上游生成量。网络断开、上游关闭与客户端取消仍可能终止请求。
- 与 Command Code 联用时配套采用 [v1.1.0](https://github.com/dude1wudv/commandcode-proxy/releases/tag/v1.1.0)。其 Messages 默认读空闲宽限为 180 秒，首字前也有 SSE 心跳；显式 `CC_STREAM_IDLE_MS` 优先，心跳不会刷新上游活动时间。
- 共享服务器只更新目标应用，保留运营方的 PostgreSQL、Redis、Compose/env 与数据卷。升级前备份数据库；应用镜像回退不等于数据库回滚，不得以旧备份覆盖运行账单。
