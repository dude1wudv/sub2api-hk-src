## 档位与计费

- 保留 HK OpenAI Fast 默认 2.5×、Ultra Fast 默认 8×，以及分组、渠道的独立档位倍率。
- 保留强制 Fast、强制 Ultra Fast、免费 Fast、免费 Ultra Fast 四个独立开关。
  可信分组强制配置优先于全局档位策略。
- 接收 Ultra Fast 模型门控：归一化后的 GPT-6 Astra、GPT-6.1 Sol 支持强制 Ultra。
  同时开启两个强制开关时，其他模型使用 Fast；仅强制 Ultra 时，其他模型沿用客户端和全局策略。
  HTTP 与 WebSocket 每次 `response.create` 均按实际出站模型判断。
  原生压缩回退换模型时，恢复原始客户端档位并重新应用分组及全局规则；
  不支持 Ultra 的回退模型不会继承前次强制 Ultra。
- 强制档位按最终出站档位计费；上游回显仍单独记录，包括权威降档提示。
  支持模型门控后的 Fast 回退，避免请求发送 Fast 却因 Ultra 开关误走降价结算。
- DeepSeek 覆盖文件中显式非负价格（包括零）作为对应字段的最终单价，不重复叠加官方高峰倍率。
  保留显式零缓存价、实测和估算缓存差异、文本有效折扣、原价工具费及现有套件规则。
- 保留 Gemini 强制缓存计费及粘性换号折扣，接收稳定会话前缀哈希。
- Vertex 多区域只对实际使用多区域的默认 token 价格应用 1.1×；
  分组和渠道自定义价格沿用配置，不额外加价。

## 网关、调度和页面

保留已确认用量与未计量尾部的断流结算、有限后台捕获和不确定计费时不重放请求。
整合 token 轮换请求捕获、错误透传保护、Grok 媒体错误、配额和模型能力等独立正确性修复。

调度快照纳入冷却账号，读取时继续按实时状态筛选；保留 HK DeepSeek 套件元数据。
保留 portal / ink、移动端布局、slow-TTFT 和既有专属分组页；
上游旧分组页、旧用户用量页继续删除，其适用功能移入 HK 页面。

以下改动按合并审阅结论暂缓接入：

- 按用户通道合并扣费的生产依赖注入；
- 跳过 HK 尾部观测的 SSE 事件快捷路径；
- 调度快照 coalescing、stale grace 和 last-used 缓存性能包；
- Messages 生命周期事件暂存与首个内容前 EOF 的重放范围扩大。
- 尚无 RelayKit 所有者接入的新增翻译语义，包括 system→developer、
  缺省 strict 注入、跨协议 metadata、Gemini 新格式/工具分块、
  xAI 工具隐藏重建和工具 schema 约束放宽。保留原始响应观察与搜索计量。

## 数据库与发布

历史迁移不改字节和校验和。新增两个上游 251 文件及
`349_group_usage_rollup_retention_nonblocking.sql`，统一 HK 保留边界和上游非阻塞重建状态。
既有 HK 数据库升级和全新迁移重放均须覆盖，防止迁移排序造成函数回退。

`deploy/upstream_release.py` 复用现有应用发布的备份、运行参数指纹、历史账单指纹、
共享容器不变性、健康和嵌入资源核对。新增迁移按精确文件名与校验和放行，
并要求候选提交的 CI 与 Security Scan 均成功。服务器从 GitHub 拉取固定提交构建，
只切换 Sub2API 镜像，保留配置、PostgreSQL、Redis、卷和构建缓存。
历史指纹针对发布前实际可见的账单；序列 ID 已分配但事务稍后才提交的新增可见行
单独记录，避免把正常并发提交误判成历史账单修改。原快照中账单的篡改和未到期删除仍阻止发布。

健康、静态资源和自动化测试不等同于真实付费调用或人工浏览器验收。
回退应用镜像不回退数据库，已经执行的新迁移与历史账单继续保留。
